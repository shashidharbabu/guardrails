# Branch Strategy

This repository uses a two-branch strategy:

## Branches

### `deploy` (Main/Production Branch)
- **Purpose**: Main branch for production-ready code
- **Protection**: Should be protected and require pull requests
- **Usage**: Only merge from `develop` after thorough testing
- **Status**: Production-ready, stable code only

### `develop` (Development Branch)
- **Purpose**: Active development branch
- **Usage**: All feature development happens here
- **Workflow**: 
  - Create feature branches from `develop`
  - Merge feature branches back to `develop`
  - When ready for production, merge `develop` → `deploy`

## Workflow

1. **Feature Development**:
   ```bash
   git checkout develop
   git checkout -b feature/your-feature-name
   # ... make changes ...
   git commit -m "Add feature"
   git checkout develop
   git merge feature/your-feature-name
   ```

2. **Deployment**:
   ```bash
   git checkout deploy
   git merge develop
   git push origin deploy
   ```

3. **Hotfixes** (if needed):
   ```bash
   git checkout deploy
   git checkout -b hotfix/issue-name
   # ... fix issue ...
   git commit -m "Fix issue"
   git checkout deploy
   git merge hotfix/issue-name
   git checkout develop
   git merge hotfix/issue-name
   ```

## Branch Protection

It's recommended to:
- Protect `deploy` branch (require PR reviews)
- Require CI/CD checks before merging to `deploy`
- Keep `develop` as the default branch for new PRs
